# Grok 语音连接检查与自动恢复

验证日期：2026-10-25。

## 需求和范围

用户要求检查真正的语音连接，并在失败后自动重连，避免反复手动恢复。此次检查覆盖语音启动失败、连接关闭、连接不回应和回复停滞。macOS 注销或重新登录不在本次验收范围。

网关每 30 秒在现有语音 WebSocket 上发送空的 `session.update`，等待新的 `session.updated`。不会创建测试对话或播放声音。该应答由 [xAI 语音协议](https://docs.x.ai/developers/rest-api-reference/inference/voice) 定义；本次也实际验证了空更新被当前服务接受。

失败后自动清理旧音频，再重新获取临时凭据并连接。重试逐步延长，最长 30 秒。原提问和桌面任务不会重发。连接关闭时立即进入恢复；连接仍打开但不应答时，由定期检查触发恢复。正在执行的工具不按普通回复停滞处理。

`/debug/voice-health` 在语音已连接时返回 HTTP 200；连接中、恢复中或不可用时返回 HTTP 503。登录错误只保留固定分类，不输出凭据或服务端原文。`action_required` 表示账户需要处理，自动重试不能替用户重新登录或适配已改变的内部接口。

## 回归验证

新增 `gateway/tests/test_gbot_voice_recovery.py`。测试通过实际 HTTP、WebSocket、语音代理和 Opus 编码链路执行；上游服务由本机测试服务器替代。

- 首次凭据请求失败后，上游恢复即可自行连通，不必让机器人重新连接。
- HTTP 服务和 WebSocket 仍打开，但服务端不确认会话时，状态为不可用。
- 服务端停止回应检查时，旧连接被替换，新连接可以再次输出语音。
- 连接关闭后自动恢复；显式停止后不再重试。
- 恢复前发出播音停止消息，释放设备的说话状态。
- 登录失效时标明需要处理账户，不暴露服务端私密字段；账户恢复后状态清除。
- 回复停滞时恢复连接，不重发原请求；等待旧播报的调用及时返回失败。

上述测试中的初始失败、回复停滞、播音停止及旧调用结束均先在缺少对应修复时失败，再在修复后通过。

相关语音、网关状态、HTTP 接口和文档检查共 193 项通过。实际安装环境保留了已有的会话恢复代码，并额外通过 89 项相关兼容性检查。Python 静态错误检查与差异空白检查通过。

## 真实上游验证

使用 `gateway/scripts/probe_gbot_voice_recovery.py` 建立独立测试连接，连接真实 Grok 上游。测试服务器只模拟本机登录桥暂不可用，不模拟成功的语音返回。

1. 首次请求失败后开启转发，代理自动连接成功，生成并收到 32 个音频帧。
2. 主动关闭这条测试语音连接后，代理自动重连，再次生成并收到 43 个音频帧。
3. 测试观察到 2 次恢复尝试，最终语音状态为 connected，静默检查成功，未读取麦克风，也未中断机器人通话。

以上帧数只是确认音频实际产生，不是性能指标。音频解码后保存在本机验证目录；没有上传账户信息或录音。
